# Wordbout 软件测试过程与优化记录

版本 0.12.0 · 2026-11-06 · 对应提交见文末

本文记录本轮完整测试过程的落地方式：测什么、怎么测、测出什么、改了什么、还差什么。
所有数字都来自仓库里的可重跑命令，不是估算。

---

## 1. 测试对象与质量目标

测试对象是 Expo SDK 54 的 React Native 应用 Wordbout（英语学习：查词 / 课本 / 练习 / 打卡 / 统计）。
它有三层可以被分开验证的东西：

| 层 | 内容 | 特征 |
| --- | --- | --- |
| 领域逻辑 | `src/domain` 下的纯函数：日期、统计、连续天数、评分、埋点分析、文本处理 | 无 IO、无 UI，最容易被测透 |
| 状态与持久化 | `AppStore` 的迁移、写入、坏数据处理 | 一次写错就会丢用户数据 |
| 界面与流程 | expo-router 页面、底栏、练习状态机、设置 | 只有真跑起来才知道通不通 |

质量目标按重要度排序，这也是后面判断先修什么的依据：

1. **正确性**：判分、打卡、连续天数、统计口径不能错，错了用户会不信这个 App。
2. **鲁棒性**：坏输入、坏存储、断网、连点、深链接直达都不能白屏或丢数据。
3. **性能**：首屏可交互、切页、提交出分的耗时，不能出现用户能感知的空白等待。
4. **完整性**：需求里的分支都要有落点，不能有按钮点了没反应。

## 2. 测试策略：三层，各管一段

### 2.1 第一层：领域逻辑单元测试（Vitest，120 条）

`tests/unit/*.test.ts`，跑 Node 环境，直接对纯函数下断言。选它的理由很简单：
这一层的输入输出是确定的，用浏览器去验证是浪费，而且失败信息一眼能定位到函数。

| 文件 | 条数 | 覆盖对象 |
| --- | --- | --- |
| `date.test.ts` | 20 | 日期键对齐、跨闰日/跨年加减、周起点为周一、月末、时长格式化进位 |
| `stats.test.ts` | 18 | 达标判定、每日重算、聚合、趋势粒度切换、水平分档 |
| `streak.test.ts` | 19 | 四种日标记、断签与补签重连、补签额度按周分组、30 天窗口边界 |
| `grading.test.ts` | 22 | 拼写判定、客观题与主观题评分、提交链路阶段、超时与失败兜底 |
| `analytics.test.ts` | 17 | 停留配对、30 分钟封顶、300ms 下限、有效停留率、点击聚合、空数据不产生 NaN |
| `text.test.ts` | 24 | 中英空格收紧、关键词切分、强调切分、词形归一、收藏夹排序与计数 |

约定：只用夹具构造数据（`tests/unit/fixtures.ts`），不 mock 时间以外的系统能力；
涉及配置的用例临时改 `appConfig` 再在 `finally` 里还原，避免测试之间串味。

### 2.2 第二层：端到端（Playwright，38 条）

跑在 `expo export --platform web` 的静态产物上，用真实浏览器操作真实界面。
这一层只验证三件单元测试管不到的事：路由与导航能不能走通、状态改完界面是否跟着变、
出错时用户看到什么。

| 文件 | 条数 | 覆盖对象 |
| --- | --- | --- |
| `smoke.spec.ts` | 4 | 引导页四个入口、同意后落主页、底栏五项与顺序、跑一圈一级页无未捕获异常 |
| `navigation.spec.ts` | 5 | 一级页切换、二级页进入与返回、深链接直接刷新、未知路由兜底 |
| `practice.spec.ts` | 6 | 空答案不能提交、提交后进结果态、任务计数 +1、连点只记一次、断点续做 |
| `calendar.spec.ts` | 6 | 周/月/年三档切换、四种标记、补签成功与额度用尽、超出 30 天窗口拒绝 |
| `settings.spec.ts` | 4 | 语言切换即时生效、字号三档、网页版通知能力说明、清缓存不动学习记录 |
| `analytics.spec.ts` | 5 | 事件写入、停留统计、点击排行、会话数、清空本机数据 |
| `robustness.spec.ts` | 8 | 坏 JSON、错误形状、旧版本迁移、越权直达、超长输入、连点、反复进出、坏数据留档 |

两条硬约定，写在 `tests/e2e/helpers.ts` 里：

- **选择器只用可访问名**（`getByRole` + `aria-label`），不碰类名与 DOM 结构。RN Web 的类名是编译产物，
  改一次样式就全变；反过来，这套用例顺带把无障碍标注也压住了。
- **文案用双语正则**，界面默认英文也接受中文，避免换个默认语言就全红。

### 2.3 第三层：性能测量（脚本化，非门禁）

`tests/e2e/perf.mjs` 在浏览器里量五个数：首屏可交互、首屏传输量、底栏切页、进入作答、提交到出分。
不设阈值门禁（本机数字波动大，设了只会变成假警报），但优化前后必须用同一脚本对比。

### 2.4 明确不做的

- **组件快照测试**：RN Web 渲染出的结构噪声大，改一个样式就全红，收益远低于维护成本。
- **视觉回归截图**：视口、字体渲染、亚像素差异在 CI 上不稳定；界面正确性用语义断言代替。
- **原生端自动化**：需要真机或模拟器集群，本轮用 web 产物 + 手工真机抽查覆盖。
  这一点在残余风险里记着。

## 3. 测试环境与运行方式

| 项 | 取值 |
| --- | --- |
| 系统 / Node | Windows 11 · Node 22.22 |
| 应用运行形态 | `expo export --platform web` 的静态产物，由零依赖静态服务器提供 |
| 浏览器 | 本机未装 Playwright 自带 chromium，用系统 Edge（`E2E_CHANNEL=msedge`） |
| 视口 / 语言 / 时区 | 390×844 · zh-CN · Asia/Shanghai（贴近手机与国内用户） |
| 并发 | 单 worker 串行，切页与提交耗时才有参考价值 |
| 产物与报告位置 | 系统临时目录（`wb-e2e-web-*` / `wb-e2e`），仓库不留截图与 trace |

```bash
npm run test:unit          # 120 条领域逻辑，约 3s
npm run e2e:build          # 导出 web 产物到临时目录（自动选最新一份给服务器用）
E2E_CHANNEL=msedge npm run test:e2e   # 38 条端到端，约 50s
E2E_CHANNEL=msedge node tests/e2e/perf.mjs   # 性能快照
npm run typecheck && npm run lint && npm run i18n:check   # 静态检查
```

`e2e:build` 刻意不写死输出目录：`expo export` 每次运行前会把输出目录整个删掉，
60 多个文件的一次性删除会被沙箱的批量删除保护拦下，所以改成每次导到一个新的临时目录，
`tests/e2e/server.mjs` 自动认最新的那份。这个坑记在这里，免得后来人再撞一次。

## 4. 用例是怎么设计出来的

不追求把用例数堆上去，每条用例都要能回答一个问题：这条分支如果坏了，用户会怎么受伤。

- **等价类划分**：时长格式化分成三档（不足 1 分钟、1 分钟到 1 小时、超过 1 小时），
  每档取一个代表值与一个档界值；日期加减分成跨月、跨年、跨闰日三类。
- **边界值分析**：补签窗口取 30 天与 31 天两侧；停留统计取 299ms 与 300ms 两侧；
  趋势粒度取 30 天与 31 天、60 天与 61 天的分界；时长进位取 59 分 30 秒与 59 分 59 秒。
- **状态迁移**：练习页是四态机 `bank → choose → answer → result`，评分又叠了
  `idle → grading → soft-pending → succeeded/failed`。用例按迁移边设计：
  空答案跨不过 `answer → result`；评分失败要停在 `answer` 且草稿还在；最后一题答完才进 `result`。
- **判定表**：达标判定由时长、任务数两个条件组合，四种组合逐一断言（都够 / 只够时长 /
  只够任务 / 都不够），并额外验证阈值改成配置后判定跟着变。
- **错误推测**：从“用户不会故意做但一定会发生”出发，列了坏 JSON、错误形状、深链接直达、
  连点两次、超长输入、反复进出同一页、跨天跨周跨月的时间跳变。
- **场景法**：核心价值链是查词 → 练习 → 打卡 → 补签 → 看趋势，端到端用例对着这条链走一遍。

## 5. 缺陷清单

这一轮共确认并修复 12 个问题。前 10 个是产品缺陷，后 2 个是测试资产自身的缺陷
（测试写错了会给人假的通过信号，同样要当缺陷记录）。

| 编号 | 现象 | 根因 | 修复 | 回归用例 |
| --- | --- | --- | --- | --- |
| D-01 | 客观题（听写、选择）提交后要等 1.8s 才出结果，按钮一直转圈 | `requestGrading` 对全题型统一模拟 1.4s 网络延迟，可客观题判分完全在本地 | 新增 `isLocallyDecidable`，客观题同步出分、不发中间态；显式传 `latencyMs` 时仍走延迟（留给超时测试） | `grading.test.ts` 同步出分两条；`perf.mjs` 提交→结果 |
| D-02 | 连点两次确认会多记一条作答，任务数 +2 | 客观题改同步出分后，按钮同一帧就恢复可点，`disabled` 挡不住第二次点击 | 提交入口加 `submitLock` ref 互斥 | `practice.spec.ts` 连点只产生一条作答记录 |
| D-03 | 埋点页会话数永远是 0 | 冷启动时埋点还没开（未同意隐私政策）就先占了 sessionId，开关打开后 `ensureSession` 以为已有会话 | `startSession` 未开启时直接返回；开关打开时补建会话 | `analytics.spec.ts` 会话数 |
| D-04 | 网页版点清空数据、清空学习记录、注销都没有反应 | RN 的 `Alert` 在 web 上是空实现 | 自建跨平台对话框（`AppDialog` / `askDialog` / `notifyUser`），替换 10 处调用 | `settings.spec.ts` 清缓存 |
| D-05 | 升级版本后全部学习记录消失 | 持久化版本号与当前不一致时直接删档重建 | 改为字段级迁移：缺字段按默认补、旧字段做映射，只在真的读不出时才回落 | `robustness.spec.ts` 旧版本数据迁移 |
| D-06 | 今天刚达标，连续天数不跟着加 | `computeStreak` 只看已落盘的每日聚合，忽略进行中的实时达标 | 传入 `todayQualified`，回溯时优先采用实时值 | `streak.test.ts` 实时达标 |
| D-07 | 做测验也算进当日任务数，打卡被刷 | `recomputeDaily` 只过滤了失败作答，没过滤测验（测验应答打 `excluded`） | 过滤 `excluded` 的作答 | `stats.test.ts` 测验不计入 |
| D-08 | 拼写里带撇号（don't）永远判错 | 归一化时把撇号一起删了，`dont` 与 `don't` 词数对不上 | 保留撇号并把弯引号统一成直引号 | `grading.test.ts` 撇号 |
| D-09 | 时长显示出现 1 小时 60 分、59 分 60 秒 | 分钟与小时各自四舍五入，进位丢失 | 先合成总分钟再拆小时与分钟 | `date.test.ts` 时长进位 |
| D-10 | 深链接直达二级页后，返回键点了没反应 | `router.back()` 在没有历史栈时不做事 | 用 `canGoBack()` 判断，否则回主页 | `navigation.spec.ts` 深链接刷新 |
| D-11 | 本地存储被写坏后，用户数据静默消失，只剩首次启动状态 | 解析失败直接返回 null，坏数据原地被覆盖 | 解析失败先把原文另存一份（`state:corrupt`）再回落 | `robustness.spec.ts` 坏数据留档 |
| D-12 | 端到端用例的迁移测试其实什么都没测 | 用例按裸键 `state` 写存储，真实键名是 `wordbout:v1:state`；底栏按 button 找、实际角色是 tab | 统一键名常量 `STATE_KEY`，新增 `tabButton()`；用例写完必须能修坏对应的代码才变红，否则不算数 | `helpers.ts` 注释与全部导航用例 |

缺陷分布值得说一句：12 个里有 7 个是测试跑起来才暴露的（D-01、D-03、D-04、D-06、D-07、D-11、D-12），
其中 D-03 与 D-04 属于“功能看起来做了、实际没生效”的一类，只靠读代码很难发现。

## 6. 性能测量与优化

### 6.1 测量方法

`tests/e2e/perf.mjs` 用同一台机器、同一个浏览器、同一份产物，测五个指标：

- 首屏可交互：从 `goto` 到引导页按钮可点；
- 首屏传输量：`performance.getEntriesByType('resource')` 里的 `transferSize` 之和，分 JS 与总计；
- 底栏切页：点击到目标页标志物可见；
- 进入作答：整页重载、选题库两次拆开；
- 提交到出分：点确认到结果按钮出现。

### 6.2 优化前后

| 指标 | 优化前 | 优化后 | 变化 |
| --- | --- | --- | --- |
| 首屏可交互 | 392 ms | 273–287 ms | −29% |
| 首屏传输总量 | 17.1 MB | 8.8 MB | −49% |
| 其中 JS | 8.65 MB | 4.83 MB | −44% |
| 其中字体 | 7.7 MB | 3.5 MB | −54% |
| 底栏切页（四项） | 34–77 ms | 29–66 ms | 基本持平 |
| 进入练习页（整页重载） | 约 470–997 ms | 141–147 ms | −70% |
| 提交到出分 | 1861 ms | 29–39 ms | −98% |

### 6.3 三处改动的依据

**一、客观题不再等模拟网络。** 这一条不是“把延迟调小”，而是先把问题说清楚：
听写与选择题的对错在本地就能判死，让它陪着主观题一起等 1.4 秒是纯粹的白等。
改完主观题仍然保留延迟（正式版那里是真接口），客观题同步出分。
所以 `grading.test.ts` 里专门加了一条断言：客观题的反馈序列只有 `succeeded`，没有 `grading`。

**二、繁体转换表不再带上整本词典。** 生成脚本原本把 `src` 下所有含中文的字符串都转成繁体，
其中包括 `src/data` 里两份词典的原始文本（单条 60 万字符与 38 万字符）。
按既有口径（`data`、`content` 保持简体、不参与本地化），把收集范围收窄到界面层目录：
生成物从 2.95 MB 降到 31 KB，整包 JS 因此少了 2.9 MB。这一改没有任何行为变化，
因为那两条巨串本来就不会被 `localize()` 查到。

**三、web 端字体改 woff2。** 同一份子集压成 woff2，体积约为 ttf 的三分之一，
`fonts:subset` 现在一次产出两种格式，`src/theme/fonts.ts` 按平台选。
原生端仍用 ttf（不支持 woff2），web 端只拉 woff2，字体传输从 7.7 MB 降到 3.5 MB。

顺带补的两个小修：`metro.config.js` 把 woff2 登记为资源扩展名（Metro 默认只认 otf/ttf），
`AppDialog` 里遗漏的“好”补进英文词表（`i18n:check` 未收录回到 0）。

### 6.4 没有做的优化

- **词典数据按需加载**：`src/data` 里两份词典合计 1.35 MB，是剩下最大的一块。
  想拆成异步分块，但 `translateWithDictionary` 是同步 API（拍照、语音两处依赖），
  改成异步会牵动整条调用链。收益约 15%，风险明显偏高，留到有明确收益的场景再做。
- **每秒 tick 的全树重渲染**：会话计时每秒更新一次 `today`，订阅 `useApp()` 的页面会跟着重渲染。
  实测切页与提交耗时都没有异常（都在 40ms 量级），暂不动；真机上如果发现卡顿，再把它拆成独立 context。

## 7. 残余风险与后续

| 风险 | 影响 | 计划 |
| --- | --- | --- |
| web 端 JS 仍有 4.83 MB | 首次冷启动要解析整包，弱网明显 | 词典分块（见 6.4），或改用按路由分包 |
| 原生端没有自动化 | iOS/Android 行为差异可能漏测 | 接 Maestro 或 Detox 跑一条核心链 |
| 单元测试无覆盖率门槛 | 新代码可能绕开已有断言 | 接 `vitest --coverage`，先只统计 `src/domain` |
| 评分仍是本地启发式 | 主观题分数只能用于趋势，不能当权威 | 换真接口后补一轮评分一致性测试 |
| AI 链路失败兜底未压测 | 30s 超时与草稿保留只做了单测 | 用拦截代理模拟超时、5xx、限流各跑一遍 |
| CI 未接入 | 依赖本地手动跑四条命令 | 加一条流水线：typecheck → lint → i18n → unit → build → e2e |

## 8. 每次改动都要跑的回归清单

```bash
npm run typecheck    # 类型
npm run lint         # 只允许 AppStore 那条既有 warning
npm run i18n:check   # 未收录 0 条
npm run test:unit    # 120 条必须全绿
npm run e2e:build && E2E_CHANNEL=msedge npm run test:e2e   # 38 条必须全绿
```

改界面文案后额外跑 `node scripts/i18n-audit.mjs`（未本地化的纯 ASCII 文案 0 处）；
改字体或子集后额外跑 `npm run fonts:subset`，它会同时产出 ttf 与 woff2 并自检缺字。

1 文档说明

1.1 编写目的与阅读方式

本文档描述Wordbout的产品定位、目标用户、功能需求与验收标准，供产品、研发、设计与测试在同一口径下工作。文档把产品决策放在功能清单之前，把功能清单放进可验收的用户故事，并覆盖商业化、指标、发布与风险。

文档分三种读法。管理者看第2章与第5章，十分钟内可判断产品要解决什么问题、分几步走、怎么收钱。设计与研发看第6至第8章，信息架构、流程与用户故事可直接转成任务。测试看第8章验收标准与第9章非功能要求，两者合起来即为用例来源。

第8章标注现状的需求均已在v0.10.0实现，可对照代码验证；标注M2、M3的是规划项。二者同章以优先级标签区分，交接时能看到已有什么、还要什么。

1.2 产品一句话定义

Wordbout是一款面向中文母语者的轻量英语学习工具：用AI把查一个词、练一道题、改一段话三件事放进同一个App，每天十到十五分钟就能完成一轮有效训练。

三个限定词各有边界。轻量排除社交、直播课、题库售卖与重度游戏化；中文母语者决定释义、批改反馈与界面语言以中文为主、英文为学习对象；一轮有效训练把衡量单位从背了多少词换成完成一次带反馈的练习，这是与同类产品最根本的差别。

1.3 术语与缩写

术语定义
课本 / 词库词库是数据单位（一批单词、释义、例句、音标的集合）；课本是词库在界面上的展示单位。用户打开的是课本，背后是一份词库。
板块 / 题型练习的两级分类。板块为听、写、说、读、译五个；题型为板块下的具体训练形式，现共九种（听写、听力理解、作句、作文、词与短语、句与段、短文、阅读理解、翻译）。
作答（Attempt）一次提交产生一条记录，含作答内容、得分、评分状态、耗时。为统计与回看的最小数据单位。
题集（Note）用户主动加入的题目集合，同时也是错题的归宿。旧称错题本，现与收藏合并为同一套数据，可逆。
打卡当日练习时长或任务数达到门槛后，把这一天计入连续练习天数。未达标的打开行为不计。
得分率某项目累计得分除以该项满分，用于让不同满分标准的题型可以横向比较（0–100%）。
AI评分调用大模型对写作、口语、翻译作答给出分数、问题定位与改进建议。九种题型中六种走此链路。
降级链首选能力不可用时按序退让的备用方案，例如翻译失败退到内置词典、AI未配置退到离线词条。
P0 / P1 / P2优先级。P0 = 缺失则产品不成立；P1 = 影响核心体验，当前里程碑内完成；P2 = 优化项，可延后。

1.4 需求编号与优先级规则

用户故事编号为US-模块代号-两位序号，模块代号取H（主页）、X（探索）、T（课本）、E（练习）、S（趋势）、O（更多）、A（账号）、P（付费）。验收标准写在故事内部，用Given / When / Then三段表达，可逐条转成测试用例。埋点事件在事件表中统一登记，故事里只引用事件名。

2 背景与目标

2.1 问题背景：三个断裂

市面上的英语学习产品大致分三类：词典类解决看不懂，背单词类解决记不住，题库与批改类解决写不对、说不出。三类产品各自成熟，但用户的学习行为是连续的，于是出现了第一个断裂：学习链路被切成三段，用户要在三到四个App之间搬运。在词典里查到的生词，很少被带进背单词列表；背完的词，很少被拿去练写作；写完的作文，没有人改。每一次搬运都是一次流失点。

第二个断裂是AI的位置。当前主流产品的AI多数停留在生成例句AI陪练对话这类辅助位，真正把AI当作评分引擎的很少。而主观题恰恰是学习者最缺反馈的地方：写作没人改、口语没人听、翻译对不对自己判断不了。选择题可以自评对错，主观题不行，这是存量产品长期没有解决的空白。

第三个断裂是重量化。备考产品以词库数量为核心卖点，两百多本词书、每日上百词任务，对目标是每天十几分钟的用户是负担。选择成本高、任务压力大、断签即放弃，是这类产品共同的留存曲线形状。

这三个断裂指向同一个位置：一个把查词、练习、AI批改放在一条链路上，且每个环节都足够轻的产品。

2.2 产品定位与价值主张

Wordbout的定位是学习闭环的最小实现。它不试图在词库数量上竞争，也不做社交与课程，只保证一件事：从遇到一个不懂的词，到能用它写出一个正确的句子，全过程不离开这个App。

能力对用户说什么实际交付的东西
查不懂就问，问了就懂对话式查询：一个词或一句话发过去，返回释义、词源、近义词、例句；可以接着追问，不用重新组织问题。
练九种练法，覆盖听说读写译五个板块九种题型的训练，每种都有题库、倍速播放、逐题结算与断点续做。
评写完有人改，说完有人听六种主观题型由AI给出总分、分项分、问题定位与改写建议，而不是只给一个分数。

这三项能力分别对应竞品的三个强项，合并在一处是产品的主要赌注。轻量是这个赌注的代价：不做的部分（社交、课程、真人服务）可能带来收入，但会破坏十几分钟一轮的节奏，因此在M1至M3内一律不做。

2.3 本期目标与度量

北极星指标定为日活跃用户数（DAU）。选它而不选注册数或下载量，是因为这个产品的价值只在当天真的练了一轮时才发生：一个下载后不打开的账号，对用户、对内容、对AI成本都是负资产。DAU同时是三件事的乘积——新增、留存、召回，任何一环恶化都会立刻反映出来，适合个人项目在资源有限时做单点判断。

2.4 非目标

明确写出不做什么，比写出做什么更能约束范围。以下六项在M1至M3内不做，任何需求若指向它们，先回到本节讨论是否修改产品定义。

  • 不做社交。没有好友、排行、学习小组、打卡分享。社交能提升短期活跃，但会把产品变成表演给谁看，与本产品的私人工具属性冲突。
  • 不做课程与真人服务。不卖课、不做一对一、不做直播。这类业务依赖供给侧，与个人项目的能力不匹配。
  • 不做题库售卖与考试报名。不代理真题版权，不接入报名入口。
  • 不做重度游戏化。不做养成、不做抽卡、不做虚拟货币。轻量的边界是打开就能练，不是打开就要玩。
  • 不做多语种。只做英语，不做日语、韩语等第二语种。
  • 不做网页版与桌面版。移动端优先，鸿蒙在M4评估，不作为承诺。

3 用户与场景

3.1 用户分层

目标用户收窄为两类主用户加一类受监管用户。三类并列会导致功能互相牵制：学生要考试词库与题型，职场要邮件与会议场景，泛学习者只想刷词。本版只服务前两类，第三类以合规方式覆盖，不做针对性功能。

层级人群核心诉求付费意愿与决策依据
P1主用户高等教育阶段学生（本科、研究生，含专升本与考研）过四六级、雅思、托福；写作与翻译没人改；想知道自己到底哪一项弱中。价格敏感，愿为能提分的能力付费，对词库多不敏感
P2次用户职场用户（入职三年内，需读写英文邮件与文档）看得懂、写得对；通勤与午休的碎片时间；不要学习计划压迫感较高。时间比钱贵，愿为少走弯路付费，对界面质感敏感
P3受监管用户中学生及其家长校内听写、默写、教材同步由家长决策，价格敏感度高；本版不做教材同步，仅保证内容与时长可控

P3的处理需要单独说明。目标用户包含中学生，意味着产品在合规上必须按未成年人可用的标准设计：不做诱导消费、不做连续签到惩罚、不做公开排行，并在M2引入监护人可见的使用时长说明。这与不做社交、不做游戏化的产品定义恰好一致，成本可控。

3.2 用户画像

画像一：备考中的大三学生。六级考了两次，第一次424分。知道自己听力弱、作文写不好，但不知道弱到什么程度。用过两款背单词App，词库背到B开头就断了。真实需求不是更多词，是告诉我作文丢在哪、怎么改。

画像二：入职两年的产品经理。每天要读英文文档、写英文邮件。查词需求高频但零散，用网页词典，查完就忘。想练写作但没有整块时间，也不想被每日任务绑架。真实需求是随手问、随手改。

画像三：高一学生与他的家长。学校每周听写，家长签字的依据是分数。孩子用手机学习，家长担心的是是在学还是在玩。真实需求是过程可见、时长可控。

4 竞品与差异化

4.1 竞品选择

选取四款产品做对照，覆盖四条不同的产品路线：百词斩代表图像记忆 + 海量词库的国民级背词路线；不背单词代表语境与例句优先的内容路线；多邻国代表游戏化课程的语言学习路线；Anki代表开放记忆卡的效率工具路线。这四款分别占据用户心智中的背词语境课程自主复习四个位置，与Wordbout可能被归入的任何一个位置都相邻。

需要提前说明调研方式的局限：以下数据来自公开资料与商店页（2026年10月），价格随地区与活动浮动，功能以公开宣传口径为准，未做全量功能实测。评分列为主观判断，判断依据写在说明列，便于他人复核或推翻。

4.2 五维横评

评分采用五分制，5分为该类目内的上限。功能集成度看是否覆盖查、背、练、评四件事；完善度看内容体量、稳定性与细节完成度；学习成本看从打开到完成一轮有效训练的步骤数与认知负担；词库完善度看词书数量、释义来源与例句质量；AI能力看AI是否进入核心链路而非点缀。

4.3 差异化主张

主张一：提问式的查词。传统词典给的是词条，用户要自己把词条套回句子。Wordbout给的是对话：把整句发过去，得到这句话的翻译、词在这个语境里的意思、容易混淆的近义词差别；不满意就接着问那如果换成另一个词呢。多轮上下文被保留，不需要每次重新描述前提。这一条对应的实现是多轮会话、意图判定（查词／问答／答不上来）与结果缓存。

主张二：全题型AI评分。九种题型中有六种是主观题，全部走AI评分，且评分结果强制包含四块内容：总分、分项分、问题定位、可执行建议。只有分数没有理由的评价对学习没有价值，因此四要素不全的评分视为不合格，这是硬性验收，不是体验优化。写作与翻译还要求给出参考改写，口语要求指出问题最集中的句子。

主张三：轻量。三个一级入口都在底栏，任何核心操作从首页出发不超过两次点击；不排学习计划、不做签到奖励、不弹营销弹窗；一轮训练的默认长度是三到十分钟。轻量的目的不是功能少，而是降低开始的成本——学习产品最大的敌人是不开始，不是功能不够。

6.3 全局交互规则

全局规则的作用是让25个页面看起来像一个产品。以下六条为强制约定，新增页面必须遵守，违反视为缺陷而非风格差异。

  • 底栏恒定五个入口，切换不做转场动画（硬切），避免每次点底栏都像进了新App。
  • 页面主操作固定在底栏。二级页的主按钮（提交、下一步、保存）一律放底栏，内容区只放卡片与表单，保证拇指可达且位置稳定。
  • 二级页有返回箭头，标题靠左，不写副标题。返回键与系统手势、Android返回键同口径，逐级返回（题目→文体→题库→退出）。
  • 空态必须给出下一步动作，不允许只显示暂无数据。无记录、无网络、未登录三种空态各有独立文案与按钮。
  • 错误态必须可恢复。AI失败给出重试按钮且保留已输入内容；网络失败给出离线可用的替代入口；不可恢复错误才允许阻断。
  • 颜色不能单独承载信息。对错、升降、选中状态必须同时有图标或文字，正文与背景对比度不低于4.5:1。

7 核心流程

7.1 查词与翻译链路

这条链路是全产品调用量最大的路径，设计目标是两秒内有东西看。因此它是一条带三级降级的链：大模型整句翻译优先，失败退到内置词典逐词对照，再失败退到提示重试但保留输入。

输入文本 → 源语言判定（自动／手动指定）→ 大模型整句翻译

├─ 成功 → 译文卡（逐句译文 + 朗读）→ 分单词释义（音标、词性、义项、例句）

├─ 超时或失败 → 内置词典逐词对照（ECDICT／CC-CEDICT）→ 标注逐词对照

└─ 词典也未命中 → 提示暂未收录，保留输入并提供重试

任一词条 → 收藏（选择收藏夹）→ 课本页收藏夹可见

规则说明
输入上限超过500字符提示分段，不阻断提交。
前缀联想英→中方向输入两个字母以上给出最多8个候选，选中候选直接查该词。
缓存同一文本命中缓存不重复请求，既省成本也保证重查结果一致。
朗读译文与词条都可朗读，语言按文本是否含汉字自动选择。
失败文案不展示原始错误码，只展示可读原因与下一步动作。

7.2 一次练习的完整链路

练习会话采用一页四板块而不是多页跳转：选题库、选文体、作答、结算都在同一路由内推进。这样做的原因有两个——评分是异步的，跨页会导致状态丢失；用户需要随时退回上一板块改选题库，多页栈会让返回行为变得不可预测。

① 选题库（等级：日常／CET4／CET6／IELTS／TOEFL）

↓ 确认

② 选文体（仅阅读与翻译两类需要；其余题型跳过）

↓ 确认，一次抽定题目队列（最多30题）

③ 作答（逐题；客观题本地判分，主观题提交后AI评分，结果就地展开不换屏）

↓ 下一题（可随时查看解析／加入题集）

④ 结算（逐题清单、正确率只统计客观题、重做本场）

↓

能力趋势页（本次记录已计入统计）

规则说明
提交后不跳解析页作答冻结在原地，底栏换成三按钮：查看解析、加入题集（可逆）、下一题。避免提交即离开上下文。
评分兜底20秒未返回提示正在评分并保留页面；30秒或报错转评分失败，请稍后重试，草稿不丢。
断点续做每题提交即写草稿；退出后练习页顶部出现继续卡片，恢复时定位到上次题号且保留已评分状态。
计时口径只在作答板块计时；切后台超过30秒暂停；结算页与选题板块不计时。
结算正确率只统计客观题（听写、听力理解、阅读理解）；主观题只列分数，不参与正确率，否则会把AI给85分算成错。

7.3 连续打卡判定链路

打卡是留存的主要钩子，也是最容易被做坏的地方。本产品的口径是任一达标：当日累计练习时长达到门槛，或当日完成任务数达到门槛，二者满足其一即计入。门槛默认5分钟或5个任务，用户可在打卡区点击圆环调整。

进入任一练习 → 启动计时（前台才计时）

↓

答题提交 → 任务数 +1（未提交即退出不计）

↓

时长 ≥ 门槛（默认5分钟） 或 任务数 ≥ 门槛（默认5）

↓ 满足

当日达标 → 连续天数 +1（以设备时区自然日零点为界）

↓

跨天未达标 → 连续天数归零，但累计天数、累计时长不清零

7.4 AI探索对话链路

探索页的形态是聊天，不是表单。用户发一句话，系统先判断意图，再决定给词条面板还是通用回答。判断错误时用户可以直接补充说明，不需要换页面重来。

输入 → 意图判定

├─ 查单词／短语 → 词条面板（释义 → 词源 → 近义词／变形／搭配 → 例句）

├─ 其他问题 → 通用回答（正文／列表／词表三种块）

└─ 无法回答 → 明确说这个问题我答不上来，并给三个可继续的方向

↓

命中缓存 → 直接返回（不产生调用）

↓ 未命中

调用模型（带最近6条上下文）→ 成功回填并写缓存 → 失败给重试

↓

回复下方3条建议追问（可点即问）→ 长按任一条可删除 → 历史面板可回翻20段

7.5 订阅转化链路（M3）

用户主动请求更强能力（切换高阶模型／打开高阶词库）

├─ 未订阅 → 能力对比弹层（快速vs高阶：速度、深度、是否含改写对照）

│　├─ 维持快速模型 → 关闭弹层，当前请求照常完成，不丢草稿

│　└─ 解锁高阶 → 权益页（19.9元/月·首月9.9元｜199元/年）→ 支付 → 服务端校验 → 即时生效

└─ 已订阅 → 直接使用高阶模型，不再二次确认

└─ 校验失败 → 提示支付已完成，权益正在同步，可手动恢复购买

设计要点有三条。第一，付费点不阻断正在进行的任务：用户拒绝升级时，当前请求仍以快速模型照常完成，只是不换档。第二，订阅状态以服务端为准，客户端缓存仅用于首屏渲染，防止越狱设备伪造。第三，高阶模型单独计量：日总调用量与单用户调用量都设上限，超限自动回落快速模型并提示原因，而不是拒绝服务——成本控制不该表现为产品不可用。

10.3 漏斗、看板与实验

第一个要看的漏斗是激活漏斗，共五步：启动 → 完成隐私同意 → 开始第一次练习 → 提交首题 → 完成一轮结算。任一步骤的流失超过25%即视为阻塞点，优先排查。第二个是付费漏斗：权益页曝光 → 点击查看权益 → 进入支付 → 支付成功，用于判断问题出在不想买还是买不成。由于订阅入口埋在高阶模型切换与高阶词库两处，曝光量会远低于按次拦截的设计，因此这个漏斗只算条件转化率（曝光后成单），不与行业付费墙曝光口径直接对比。

看板按周更新三张：增长看板（新增、留存、渠道）、学习看板（打卡率、完成任务数、题型分布）、质量看板（AI成功率、P95延迟、崩溃率）。实验在M3之后开展，M1至M2样本量不足，不做A/B，改为定性访谈加漏斗观察。

11.2 灰度与回滚

发布分三级：内测（本人与三名种子用户）、小范围（一个班级或一个社群，约30人）、全量。每一级至少停留三天，观察崩溃率与AI成功率两个硬指标，任一超过阈值即停止扩大范围。回滚以服务端开关为第一手段：AI模型、付费墙、新题型都挂在远程配置上，出问题先关开关，不带病发版。客户端保留上一版本的安装包与数据迁移脚本，回滚时保证记录不丢。

11.3 上线检查清单

  • 隐私政策与用户协议正文齐备，首次启动有同意流程，未同意时相机与麦克风功能不可用。
  • 客户端不含任何模型密钥、测试账号与调试入口；日志不打印用户文本。
  • 三语（简中、繁中、英文）逐页走查，无未翻译文案与断行错位。
  • 断网、超时、5xx三类故障注入通过，评分失败不丢草稿。
  • 打卡口径在练习页、趋势页、学习统计三处数值一致。
  • 数据导出可打开，删除全部记录后四处统计同步清空。
  • 深浅色与系统字号最大档下，无遮挡、无重叠、无截断。
  • 无障碍走查：读屏可读出题目与按钮，对比度达标。
  • 埋点事件按清单上报，字段无缺失，可查到一次完整练习。
  • 应用商店素材（截图、简介、关键词）与真实功能一致，不宣称未实现的能力。
